# ADR-lite 模板（上限 1 页）

> 用法：复制下表填写，字段不得增删。写不满不是问题，写超了就是没想清楚。
> 目的不是留档，是让另一个人在 5 分钟内判断"这个方案对不对"。

```markdown
# ADR: <一句话说清要解决什么>

## 问题
<要解决什么；不解决会发生什么。≤5 行。>

## 约束
- <必须兼容的现状：版本、协议、调用方、数据量、上线窗口>
- <不能动的东西：表结构、接口路径、公共契约>

## 备选（≥2，各 3 行）
### A. <名称>
做法：<一句话>
代价：<会变难/变慢/变复杂的东西>
选它的条件：<什么情况下它更好>

### B. <名称>
做法：
代价：
选它的条件：

## 选定与理由
<为什么是它；为什么不选其他。≤10 行。>

## 接口契约
<代码：签名、数据结构、错误语义。禁止用散文描述接口。>

```java
// 3 个调用示例，覆盖：正常、边界、失败
```

## 非目标
- <本次明确不做的事；必须非空>

## 风险与回滚
- 会怎么坏：<可观测现象>
- 怎么退：<开关 / 回滚步骤 / 数据修复>

## 开放问题
- <真问题；写"暂无"通常意味着没审出来>
```

## 填写质量的自检

| 检查项 | 不合格的样子 |
|---|---|
| 问题段 ≤5 行 | 用 3 段背景铺垫才说到正事 |
| 备选 ≥2 | 只写"方案：A"，然后论证 A 很好 |
| 每个备选有代价 | 只写优点 |
| 契约是代码 | 用"提供查询能力""支持扩展"描述接口 |
| 非目标非空 | 写"无" |
| 风险可观测 | 写"注意性能"这种无法验证的话 |

## 长度

正文（不含契约代码）**不超过 60 行**。超了先删"背景"和"价值"段落——那两段几乎不含决策信息。
