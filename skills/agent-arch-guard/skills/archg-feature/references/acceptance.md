# 验收口径模板

> 10 分钟能填完。填不出来，说明需求还没定，不要进设计。
> 它替代不了需求文档，但它是**唯一能判断"做完了没有"的东西**。

```markdown
# 验收：<一句话说清这条需求>

## 谁用
- 角色：<员工 / 合作伙伴 / 系统调用>
- 入口：<从哪个页面/接口进来>

## 什么数据
- 来源：<哪张表 / 哪个外部系统>
- 量级：<条数、频率；没有量级的验收都是空话>
- 样例：<一条真实或接近真实的数据，写在下面>

## 成功长什么样（必须可观测）
1. <例：提交后 3 秒内审批单出现在任务中心，状态为"待审批">
2. <例：审批通过后，供应商状态从"待准入"变为"已准入"，且写一条操作日志>

## 失败怎么办
| 情况 | 用户看到什么 | 系统做什么 |
|---|---|---|
| <数据不存在> | <明确提示，不是 500> | <不写脏数据> |
| <外部系统超时> | <可重试提示> | <抛异常让 MQ 重试 / 不回滚已提交部分> |

## 怎么验证（人照着能复现）
1. <前置数据准备>
2. <操作步骤>
3. <观察点>
4. **反例**：<故意违规操作，应被拒绝，且提示正确>

## 不做什么（非目标）
- <本次明确不做的：批量导入、历史数据迁移、多语言……>

## 验收人
- <姓名/角色> —— 由他对"做完了没有"签字
```

## 三条硬要求

1. **成功条件必须可观测**。"功能正常""体验流畅"不算，必须能写出观察点和期望值。
2. **必须有反例**。只测正例的验收，等于没验收——真实问题几乎都出在异常分支。
3. **必须有人签字**。"验收人"不能是写代码的那个人，也不能是 agent。

## 常见不合格写法

| 写法 | 问题 |
|---|---|
| "支持供应商资质审核" | 没有观察点，无法判断做完 |
| "性能良好" | 没有量级和阈值 |
| "兼容后续扩展" | 无触发条件的范围膨胀 |
| "异常情况妥善处理" | 没说看到什么 |
| 验收人填"开发自己" | 没有第二双眼睛，AI 生成 + AI 验收 = 无人验收 |
