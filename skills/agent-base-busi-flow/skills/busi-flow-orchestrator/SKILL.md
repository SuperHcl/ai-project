# 8 步流程编排器

## 定位

**meta-skill：调度其他 9 个 Skill，自身不产业务文档**。处理 3 类问题：

1. **入口路由**：用户说"开始 v2.33.0 开发"应该跳到哪个 Skill？
2. **进度持久化**：用户中断 3 天后回来，怎么知道当前停在哪一步？
3. **检查点把关**：5 道人工审查检查点的统一展示与确认机制

> ⚠️ 本 Skill **不调用**任何业务输入输出，只读写 `.flow-state.json` + 调度其他 Skill。如果发现自己开始在写需求 / 接口 / 代码，说明走错 Skill 了。

## 触发词路由

### 启动类

| 触发词 | 行为 |
|---|---|
| "开始 v{X} 开发" / "启动 v{X}" / "/start v{X}" | 创建 `iterate/v{X}/` + 询问业务模块名 → 创建 `iterate/v{X}/{业务模块}/` + 初始化 `.flow-state.json` → 跳 B2 |
| "开始 v{X} {业务模块}" | 同上，直接使用指定模块名 |
| "新增模块" / "/new-module" | 同一 v{X} 下创建另一个 `{业务模块}/` + 独立 `.flow-state.json` |
| "继续" / "继续开发" / "/resume" | 读 `.flow-state.json` → 跳到 `current_step` |
| "继续 B{N}" | 显式跳到 B{N}（验证前置已完成）|

### 查询类

| 触发词 | 行为 |
|---|---|
| "状态" / "进展" / "/status" | 读 `.flow-state.json` 输出可视化进度 |
| "下一步" / "/next" | 列出当前步骤下一步要做的具体动作 |
| "本版本待澄清" / "/blockers" | 列 `.flow-state.json` blockers 数组 |

### 检查点类

| 触发词 | 行为 |
|---|---|
| "OK" / "通过" / "审过" / "确认" | 当前检查点放行 → 进下一步 |
| "不过" / "驳回" / "回去改" | 当前步骤标 `in_progress`，等待修订 |

### 控制类

| 触发词 | 行为 |
|---|---|
| "重做 B{N}" / "/redo B{N}" | 警告影响面 → 用户确认 → 回退 `.flow-state.json` |
| "跳过 B{N}" / "/skip B{N}" | **强烈警告**（破坏流程完整性）→ 要求显式理由 → 二次确认 |
| "暂停" / "/pause" | 当前状态原样保存，输出"恢复指令"提示 |

## 状态文件 `.flow-state.json`

位置：`iterate/v{X}/{业务模块}/.flow-state.json`（**每模块一份**，模块间流程状态独立）

结构：

```json
{
  "version": "v2.33.0",
  "module": "国家模块",
  "started_at": "2026-06-15T09:00:00+08:00",
  "last_updated": "2026-06-15T15:30:00+08:00",
  "current_step": "B5",
  "step_status": "in_review",
  "completed_steps": ["B2", "B3", "B4"],
  "checkpoint_history": [
    {"id": "C1", "step": "B4", "passed_at": "2026-06-14T18:00:00", "approved_by": "user"}
  ],
  "blockers": [
    {"id": "BLK-1", "from": "B3", "desc": "X 字段是否需脱敏未澄清", "severity": "high"}
  ],
  "skipped_steps": [],
  "notes": [],
  "dev_context": {
    "author": "Hu.Changliang",
    "b4_mode": "dual",
    "commit_lang": "中文"
  }
}
```

字段语义：

| 字段 | 含义 |
|---|---|
| `current_step` | 当前停在哪一步：`B2..B9` |
| `step_status` | `not_started` / `in_progress` / `in_review`（等检查点）/ `done` |
| `completed_steps` | 已完成的步骤清单（全部含检查点通过）|
| `checkpoint_history` | 5 道检查点的通过记录 |
| `blockers` | 待澄清未决的阻塞项（B3/B5/B7 来源），影响 push |
| `skipped_steps` | 显式跳过的步骤（要求理由）|
| `dev_context.author` | B7 启动前问到的开发者姓名，用于新增文件 `@author` |
| `dev_context.b4_mode` | `dual` / `single`，决定 B7 阶段 0 是否跳过 Controller 生成 |
| `dev_context.commit_lang` | `中文` / `英文`，决定 B7 commit message 模板 |

**强约束**：每次步骤切换、检查点通过、blocker 增删 → **立即更新** `.flow-state.json` 后再说话。**禁止口头说"已完成 B4"但 state 未更新**。

## Skill 链调度

```mermaid
graph LR
  Start[用户启动] --> B2[B2 解析需求]
  B2 --> B3[B3 澄清]
  B3 --> B4[B4 接口文档]
  B4 -.C1.-> B5[B5 设计文档]
  B5 -.C2.-> B6[B6 AI 规格书]
  B6 --> B7[B7 编码循环]
  B7 -.C3.-> B8[B8 集成测试]
  B8 -.C4.-> B9[B9 收尾]
  B9 -.C5.-> Done[完成]
```

**调度规则**：

1. 上一步 `step_status = done` 才允许跳下一步
2. 检查点 `Cn` 未通过不允许跳过其后置步骤
3. `B1 busi-coding-rules` 是 **always-on**，不在链里，B7 编码时自动加载
4. 调度跳转的实现：本 Skill 提示用户"现在进入 B{N}，触发 `busi-{name}` Skill"——具体执行让对应 Skill 接管

## 5 道人工审查检查点

| 编号 | 触发位置 | 主审 | 检查重点 |
|:---:|---|---|---|
| **C1** | B4 出口 | 后端 reviewer + 前端 | 接口路径 / 字段类型 / 鉴权 / 错误码 |
| **C2** | B5 出口 | 前端 + 测试 + reviewer 三角度 | 数据模型 DDL / 决策权衡 / 异常 6 类 / 测试要点 |
| **C3** | B7 出口（含其内部阶段 0 接口骨架小卡口）| reviewer | 编码 + 单测全过 / 实施顺序符合 B6 §五 |
| **C4** | B8 出口 | 测试 + reviewer | 集成测试全绿 / 覆盖矩阵 5 类齐 |
| **C5** | B9 段 5 push 前 | 用户最终决定者 | 完整性审计 / CHANGELOG / ⚠️ 无遗留 ❓ |

### 统一展示模板

每道检查点到达时，本 Skill 主导按统一模板输出，**禁止各 Skill 自行发明展示格式**：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🚦 检查点 C{n}：{B{N}} 出口审查
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - {产物 1 路径}（行数 / 关键指标）
  - {产物 2 路径}

✅ 自检通过项：
  - {对应 Skill 自检清单}

⚠️ 遗留 / 待跟进：
  - {如有 blocker，列在这里}

👥 建议主审角色：
  - {根据 C{n} 的主审清单}
```

**绝对禁止**：跳过检查点自动进入下一步。即使用户连续说"继续 B5 / 继续 B6"，到达检查点时本 Skill 必须**强制停下**等显式确认。

## 中断恢复

### 用户回来说"继续"或"状态"

执行步骤：

```
1. 找到最新版本目录：iterate/v{X}/
2. 列出该版本下所有子目录（业务模块）及其 .flow-state.json
3. 如多个模块进行中 → 询问用户继续哪个
4. 读选中模块的 .flow-state.json
5. 输出可视化进度（参见展示模板）
6. 给出"下一步动作"明确指令
```

### 跨会话恢复

新会话启动时如发现工作区有 `iterate/v{X}/{业务模块}/.flow-state.json` 且 `current_step != B9` → 主动告知：

```
检测到 v{X}/{业务模块} 开发进行中（停在 B{N}，状态：{status}）。
需要"继续开发"，还是开始新任务？
```

不擅自继续——等用户显式选择。

## 重做与跳过

### 重做某步（"重做 B5"）

执行：

```
1. 评估影响面：
   - B5 重做 → B6/B7/B8/B9 全部失效（已生成的代码 + 测试可能过时）
2. 列出受影响产物清单 + 警告
3. 用户二次确认（必须显式说"确认重做"，不接受"OK"等含糊回复）
4. 回退 .flow-state.json：
   - completed_steps 移除 B5 之后的所有步骤
   - current_step = B5
   - step_status = in_progress
   - checkpoint_history 移除 C{≥2} 记录
   - 写 notes：{时间} 用户主动重做 B5，原因 {...}
5. 提示用户：是否需要先把已生成的下游产物归档备份（建议归档）
```

**强约束**：重做不删除已有文件，只重置状态——具体哪些产物需要更新由对应 Skill 接管时判定。

### 跳过某步（"跳过 B5"）

**强烈警告**模板：

```
⚠️ 跳过 B5（设计文档）会破坏流程完整性：
  - 前端 / 测试无法并行展开
  - B6 AI 规格书将缺少决策依据
  - B7 编码 AI 缺少 DDL / 流程时序参考
  - 后续 review 困难

确认跳过的常见正当理由：
  - 极小改动（< 50 行 diff，单字段调整）
  - 紧急 hotfix（已与 reviewer 口头对齐方案）

请提供具体理由：
```

用户给出理由后写入 `skipped_steps`：

```json
{
  "step": "B5",
  "reason": "热修：补 X 字段索引，不涉及业务逻辑",
  "skipped_at": "...",
  "approved_by": "user"
}
```

`B9 段 1 完整性审计` 会扫描 `skipped_steps` 并在 retrospective 中显式列出，避免"流程被悄悄绕过"。

## AI 反模式

1. **越权干活** —— 本 Skill 是调度器，开始写需求 / 代码 / 测试就违反职责
2. **状态漂移** —— 口头说"完成 B4"但 `.flow-state.json` 没更新 → 下次恢复信息错乱
3. **跳过检查点** —— 用户连续说"继续"就一路冲到 B9 → 必出线上事故
4. **不读状态就动作** —— 用户说"继续"，没读 `.flow-state.json` 就猜下一步
5. **重做不评估影响面** —— 直接回退状态没警告下游产物会失效
6. **跳过不要求理由** —— 跳过 = 隐性技术债，必须显式记录
7. **检查点展示格式各异** —— 让用户每次都重新理解 → 必须用统一模板
8. **同时多版本并行** —— 同一仓库同时跑 v2.33.0 和 v2.34.0 两个 `.flow-state.json` → 容易串数据，应警告用户先收尾一个再开下一个
9. **主动调用其他 Skill 的内部步骤** —— 应只到"提示进入 B{N}"为止，让对应 Skill 自己接管

## 业务服务侧 overlay 可补充

| 内容 | 用途 |
|---|---|
| 版本号格式 | `v{x.y.z}` 还是 `release-{x}` 等 |
| 多版本并行策略 | 默认禁止；某些大型项目可能 2 个版本同步推进，需 overlay 显式允许 |
| 检查点主审角色映射 | 项目固定的 reviewer 名单 / 群组 |
| 状态文件存放位置 | 默认 `iterate/v{X}/`，敏感项目可改到 `.git/` 同级隐藏目录 |
| 自动通知机制 | 检查点到达时自动发钉钉 / 飞书（默认无，仅文字提示）|
