# AI 开发规格书

## 定位

**8 步流程的第 5 步，专给编码 AI 看**。B5 是给前端/测试/reviewer 看的业务语言；B6 是给 B7 编码 AI 看的工程装配清单——粒度更细、表达更刚性。

> **强约束：不重抄 B5 已有内容**。DDL、决策权衡、流程图全部引用回 B5 文件，B6 只产 B5 没给的东西。
>
> 否则 B5/B6 必合并，本 Skill 无存在意义。

## 与 B5 的边界

| 内容 | B5（人类可读）| B6（AI 装配清单）|
|---|:--:|:--:|
| 业务背景 | ✅ | ❌ 引用 B5 |
| 决策权衡 | ✅ | ❌ 引用 B5 |
| 流程时序图 | ✅ | ❌ 引用 B5 |
| 状态机 | ✅ | ❌ 引用 B5 |
| 数据模型 DDL | ✅ | ❌ 引用 B5 |
| 异常 6 类 | ✅ 描述 | ❌ 引用 B5 |
| **文件清单（路径级）** | ❌ | ✅ |
| **类与方法签名** | ❌ | ✅ |
| **实施顺序（编译可过的拓扑序）** | ❌ | ✅ |
| **TDD 测试用例清单** | ❌ | ✅ |
| **AI 编码防呆提醒** | ❌ | ✅ |

- `iterate/v{版本}/{业务模块}/01-需求内容.md`（B2/B3 产物）
- `iterate/v{版本}/{业务模块}/02-接口文档-内部.md` / `02-接口文档-外部.md`（B4 产物）
- `iterate/v{版本}/{业务模块}/03-设计文档.md`（B5 产物）
- B4-B 代码契约占位（如双产物模式已开启）：读现有 Controller/Form/Vo 类，**B6 不重复列举其字段**，仅在§二文件清单中标明「已存在（B4 占位）」
- 业务服务侧 `.agent/coding-rules.md`（拿包路径前缀、模块名、SDK 归口）
- 现有代码（确认现有类/方法位置，**只读不改**）

## 输出

```
iterate/v{版本}/{业务模块}/
├── 04-AI开发规格书.md   ← 模块主文档（文件清单 + 类签名 + 实施顺序 + TDD 用例清单）
```

模块内如需多需求拆分为多个类别，可在主文档内采用「模块-A 需求 / 模块-B 需求」二级章节结构，不再拆多文件。

## 步骤

### 步骤 1：读全输入

并行读 B2/B4/B5 全部产物 + `.agent/coding-rules.md`。**禁止跳过 B5**：B5 缺失则中断，提醒用户回去做 B5。

### 步骤 2：先列每个需求的"文件清单"骨架

不要先填类签名，先把**第二节文件清单**列出来给用户看一眼："这次改动涉及 N 个文件，新增 X / 修改 Y / 删除 Z。文件清单是这些，对吗？"

用户确认后再继续填后续节。

### 步骤 3：按节顺序填充（不跳节）

**必读** [`references/04-dev-spec.template.md`](./references/04-dev-spec.template.md) 作为输出格式骨架，依序写 §一 → §七，**禁止跳节**。原因同 B5：跳节会前后矛盾。

### 步骤 4：自检 5 条

写完每篇对照：

1. ✅ 没有重抄 B5 内容（DDL / 决策权衡 / 流程图全部用引用而非复制）
2. ✅ 文件清单都是从仓库根的相对路径，AI 能直接用
3. ✅ 类签名带完整参数类型 + 返回类型 + 关键注解
4. ✅ 实施顺序图给的是拓扑序（每步 `mvn compile` 可过）
5. ✅ TDD 用例清单覆盖 B5 §七 异常 6 类

任一不过 → 重写该节。

### 步骤 5：写 `00-AI开发规格书.md` 索引

索引格式见 [`references/04-dev-spec.template.md` §索引文件模板](./references/04-dev-spec.template.md)，包含模块索引 / 全局实施顺序（mermaid）/ 全局约束三段。

### 步骤 6：人工审查 & 衔接

写完后**主动告知**：

```
开发规格书已就绪：
- N 个需求模块 / 共 K 个文件改动 / M 条 TDD 用例
- 实施总顺序：…

可以开始 `busi-dev-loop` 进入编码循环。是否启动？
```

不自动跳，等用户确认。

## AI 反模式

1. **重抄 B5** —— DDL / 流程图 / 决策权衡复制粘贴 → B5/B6 必合并，违反职责拆分
2. **文件路径不全** —— "order-svc 里那个 service" / "改一下 controller" → AI 没法编码
3. **方法签名缺类型** —— "新增 create 方法" 没说参数和返回 → AI 必猜
4. **实施顺序乱** —— 先改 Controller 调一个还不存在的 Service 方法 → 编译都不过
5. **TDD 用例缺失** —— 直接写实现 → 边界异常没保障
6. **越界写代码** —— 写出 `public Long create(...) { ... 实现 ... }` → 这是 B7 的事
7. **防呆清单凑数** —— 没特殊风险硬编 5 条"注意空指针" → 通用条已在 `busi-coding-rules`，重复浪费
