## 四、关键流程

### 4.1 {流程 1 名称} - 时序图

只画跨模块 / 跨服务的交互，单服务内的方法调用不画。

```mermaid
sequenceDiagram
  前端->>order-svc: POST /api/v1/order
  order-svc->>inventory-svc: Feign 扣减库存
  inventory-svc-->>order-svc: 200 OK
  order-svc->>DB: INSERT order
  order-svc-->>前端: 200 OK + orderId
```

每张图配 1-2 句文字说明，不要让读者自己推。

### 4.2 {流程 1 名称} - 业务流程图（决策分支）

仅使用 mermaid 基础语法：方向 `flowchart TD`、`([])` 起止节点、`[]` 动作节点、`{}` 判断节点。**禁止 `style` 样式定义**。

```mermaid
flowchart TD
  A([POST /api/v1/order]) --> B[参数校验]
  B -->|不通过| E1[抛 PARAM_ERROR]
  B -->|通过| C{库存足够?}
  C -->|否| E2[抛 STOCK_NOT_ENOUGH]
  C -->|是| D[INSERT 订单 + 扣减库存]
  D --> F([返回 success])
```

流程图说明需明确列出关键决策分支（状态校验 / 数量校验 / 并发分支）与对应错误码。

## 七、异常与边界

| 场景 | 处理 | 风险等级 |
|---|---|:--:|
| 空数据 | … | 低 |
| 并发提交 | 唯一索引兜底 + 业务返回友好错误 | 中 |
| Feign 超时 | 重试 N 次 + 降级返回 | 高 |
| 权限缺失 | 返回 403 + 错误码 | 中 |

**至少覆盖**：空数据、并发、超时、权限缺失、历史数据兼容、灰度 6 类（不适用就显式标"N/A，理由 …"）。

## 八、安全 & 性能

- **鉴权**：接口鉴权方式（已在 B4 接口文档定，这里复述）
- **数据隔离**：是否需按租户/门店/组织过滤
- **敏感字段**：是否需脱敏 / 加密
- **预估 QPS / 数据量**：列表接口预估行数、批量接口最大批量数
- **索引设计**：每个新查询走哪个索引，避免全表扫描

## 九、测试要点（给测试同学看）

| 用例类型 | 关键场景 |
|---|---|
| 正向流程 | 主流程完整路径 1-2 条 |
| 边界 | 空 / 单条 / 批量上限 / 跨周期 |
| 异常 | 网络中断 / 数据冲突 / 权限不足 |
| 兼容 | 历史数据 / 老版本前端调用新接口 |
| 性能 | 列表分页极限 / 批量接口上限 |

## 十、上线 / 灰度 / 回滚

- **上线步骤**：先发 DDL → 后发应用 / 先灰度 N% / 全量
- **回滚条件**：什么指标超阈值就回滚（错误率 / 延迟 / 业务侧反馈）
- **回滚动作**：是否需要回滚 DDL（一般尽量做向后兼容的 DDL，不需回滚）
